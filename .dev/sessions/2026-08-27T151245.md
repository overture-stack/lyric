Added a GET endpoint to retrieve a submission file's validation errors as a normalized, field-level report, resolving the format question the "download error report for a file" roadmap item had left open.

- `packages/data-provider/src/utils/submissionUtils.ts`: added `mapSubmissionRecordErrorsToFieldErrors`, flattening any `SubmissionRecordError` variant (dictionary/schema/field validation errors, plus this repo's own `UNRECOGNIZED_VALUE`/`CONFLICTING_ACTION`) into `{ fieldName?, fieldValue?, reason, message }`; `INVALID_BY_RESTRICTION` expands into one entry per failed restriction
- `packages/data-provider/src/utils/types.ts`: added the `SubmissionRecordFieldError` response type
- `packages/data-provider/src/utils/schemas.ts`: added `submissionErrorsRequestSchema` (`fileId` required query param)
- `packages/data-provider/src/services/submission/submissionService.ts`, `src/controllers/submissionController.ts`, `src/routers/submissionRouter.ts`: added `GET /:submissionId/errors?fileId=` end to end; 404s when the file doesn't belong to the submission
- `apps/server/swagger/submission-api.yml`, `swagger/schemas.yml`: documented the new endpoint and `SubmissionErrorsResult` schema
- `.dev/tech-debt.md`: narrowed "download error report for a file"/"...as a zip" to just the remaining Content-Disposition/zip framing, now that the report format and JSON retrieval exist
- Tests: unit coverage for `mapSubmissionRecordErrorsToFieldErrors` across every error reason (`test/unit/utils/submissionUtils.spec.ts`); integration coverage against a real Postgres container for the happy path, an errorless file, a missing `fileId`, and a file not belonging to the submission (`test/integration/routers/submission/submissionRouter-errors.spec.ts`)
